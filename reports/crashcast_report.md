# CRASH TEST

## Spatiotemporal Traffic Collision Risk Forecasting

**Applied urban safety analytics / research release 1.0**

### Executive summary

CrashCast estimates relative collision risk for the next week across San Diego
Police beats. It is deliberately an aggregate forecasting study, not an
individual-crash or street-level prediction system. The analysis uses the City
of San Diego's police traffic-collision basic reports and evaluates forecasts
chronologically on the full 2025 calendar year.

The selected Poisson gradient-boosting model achieved a held-out count MAE of
0.698 collisions per beat-week, compared with 0.888 for a seasonal-naive
baseline. These numbers are generated by `scripts/run_research.py` and are not
valid if the saved experiment artifacts are absent or regenerated from a
different source snapshot.

### Data provenance and scope

The primary source is the City of San Diego Police traffic collision basic
reports dataset. Each record is a police report and includes report date/time,
police beat, injuries, fatalities, and hit-and-run status. The source is
updated daily, excludes many property-damage-only incidents, and does not
represent freeway incidents handled by CHP. CrashCast removes duplicate report
IDs and invalid date/beat records.

The public source provides block-level address fields rather than verified
collision coordinates. Therefore CrashCast uses **police beats** as the spatial
unit. It does not geocode records, draw invented points, or claim road-segment
or individual-crash precision. The traffic-count dataset is retained in source
provenance but is not used as an exposure adjustment because there is no
validated beat-to-segment crosswalk in this release.

### Research question and target

For every police beat and Monday-starting week, the target is the following
week's reported collision count. A secondary classifier estimates whether the
following week contains one or more reports. Forecasts are intended for
relative comparison of aggregate areas, not causal inference.

### Features and leakage prevention

Features include previous weekly counts (1, 2, 4, 8, 12, and 52-week lags),
trailing 4, 12, and 52-week count means, shifted trailing injury/fatality/
hit-and-run totals, a categorical beat code, and cyclical week-of-year terms.
Every rolling feature is shifted one week before use. No feature uses a future
collision, and the last incomplete source week is excluded.

### Validation

The split is chronological: training through 2023, validation during 2024,
and a fully held-out 2025 test period. Model capacity is selected on validation
MAE before fitting the selected model on training plus validation data. The
reported test period is never used for selection.

Metrics include MAE, RMSE, and Poisson deviance for counts, plus average
precision and Brier score for next-week occurrence. Ranking quality should be
interpreted with the count metrics and base rate, not as a claim of calibrated
individual-crash probability.

### Findings and limitations

The model improves aggregate count MAE over the seasonal baseline in this
source snapshot. Temporal history is expected to be influential; permutation
importance measures predictive association, not causal effect. Reporting,
enforcement, and exposure vary across time and geography. Police beats are
administrative units, and missing/property-damage-only/freeway coverage limits
generalization. CrashCast should not be used for enforcement allocation,
insurance decisions, or decisions affecting individuals.

### Reproducibility

Download the official CSV into `data/raw/pd_collisions_datasd.csv`, install
the project dependencies, then run `PYTHONPATH=src python scripts/run_research.py`.
The pipeline writes checksums and schema/missingness statistics to
`data/provenance.json`, numerical outputs to `experiments/results/`, and
figures to `reports/figures/`. Raw downloads and row-level outputs are excluded
from Git to avoid redistributing source data without review.
